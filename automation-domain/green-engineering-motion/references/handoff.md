# 單頁任務提示、交接欄位與多 agent 分工

每個新對話貼一份任務。填入頁碼和最想強調的內容即可；若重點還沒決定，可請 agent 從原頁選擇並說明。`$green-engineering-motion` 是技能名稱；沒有自動載入技能的對話，請改為「讀取技能資料夾內的 SKILL.md」（技能資料夾 = 本檔上一層，記為 <SKILL_DIR>）。

## A. 一頁一個重點動畫

```text
請使用 $green-engineering-motion 製作這門課程的單頁重點動畫。
若技能沒有自動載入，先讀取技能資料夾內的 SKILL.md（<SKILL_DIR>/SKILL.md）。
簡報：<SLIDES>.pptx 第【頁碼】頁；專案資料夾：<PROJECT>/（由 <SKILL_DIR>/templates/single-page/ 複製）。

來源：<SLIDES>.pptx
頁面：第【填頁碼】頁，包含封面、以 PowerPoint 實際編號為準。
頁面標題：【可填，方便核對】
這頁希望觀眾理解：【填一個主要重點；也可請你讀原頁後判斷】

交付形式：一個能獨立播放的重點動態圖示，方便放入該頁課程影片。
背景：【依原頁／白底／透明，擇一】
構圖：預設使用左側 65–70%，右側保留老師人像；明確指定全頁面時才使用全幅。
文字：教學文字最小 40 px（簡報 20 pt）、粗體只用於標題與關鍵詞、字重明確指定；
      原素材的資料來源保留，來源附註最小 24 px，並避開左下角藍色裝飾。
片長：【指定秒數；未指定時請依教學需要安排】
動作：【可描述流向、連動、順序或要突出的部件；其餘由你設計】

使用 Three.js，1920×1080、60000/1001 fps。
先實際檢視本頁，沿用可用的簡報素材與術語；插圖必須可辨識、幾何正確。
若有口白，先做逐字對位，元素在關鍵詞前 ≤ 0.2 s 才進場。
採快速聚焦、清楚停留、適度卡通感和準確落位，依本頁內容安排節奏。
片頭專案僅作動作與技術參考，本頁採自己的教學構圖。

工作目錄：<PROJECT>/（複製 <SKILL_DIR>/templates/single-page/）
預覽埠：【填可用埠；也可由你選擇並回報】
各頁獨立製作，原簡報、共用素材和既有片頭作為唯讀來源。

請完成實作、實際成片檢查並啟動 HTML 預覽伺服器。
交付程式、所需素材、MP4（透明背景則交付保留 alpha 的格式或 PNG 序列）、
最終靜格，以及簡短的執行說明和已驗證項目。
```

## B. 透明動態圖示，供剪輯軟體疊加

```text
請使用 $green-engineering-motion。
若沒有自動載入，讀取技能資料夾內的 SKILL.md。

為 <SLIDES>.pptx 第【頁碼】頁，
製作【物件或關係】的透明動態圖示，教學重點是【重點】。

圖示將疊在原頁影片上，位置／可用區域為【座標或畫面描述】。
未另行指定時，內容只使用畫面左側 65–70%，右側保留老師人像。
教學文字最小 40 px；原素材的資料來源保留，來源附註最小 24 px，並避開左下角藍色裝飾。
保留文字／符號：【填必要標籤】。
動作是【描述動作】；結尾【停留／循環】。

Three.js、1920×1080、60000/1001 fps，長度【秒數或請你安排】。
每個輸出影格需保留 alpha；提供 PNG 序列或已驗證的透明影片（ProRes 4444），
另附能切換淺／深底檢視透明邊緣的 HTML 預覽。

在 <PROJECT>/（複製 <SKILL_DIR>/templates/single-page/）獨立製作。
自行選擇可用預覽埠，實際檢查圖示內容、影格規格和透明度後交付。
```

## C. 整集口白影片

```text
請使用 $green-engineering-motion，製作第【N】集的口白教學 MG。
來源：口白／成片【路徑】、老師簡報【<SLIDES>.pptx 與頁面 PNG 資料夾 <SLIDES_DIR>/】、逐字稿【有／無，無則轉錄】。
以 <SKILL_DIR>/templates/episode/ 為範本複製成 <PROJECT>/（episode-00N-短名）。
先做逐字對位與段落表給我確認，再開始建置；每輪回饋前先備份 layout.json 並跑 idcheck。
交付：每段透明 MOV＋完整原音預覽 MP4＋verification.json＋對位表＋關鍵靜格與分鏡。
```

## 每頁／每集完成後的交接

在自己的資料夾（README 或 `review/`）留下簡短說明：

- 原始頁碼／標題、來源版本、教學重點。
- 動態物件、動作順序與最後位置，哪些可調整。
- 畫布、精確 FPS、總影格數、實際片長、背景／alpha（ProRes 標示見 [qa-checklist.md](qa-checklist.md)）。
- 預覽埠、啟動方式、輸出與素材路徑。
- 已做的實際檢查，以及仍需使用者決定的內容。

整集另附：逐字對位檔與 `review/cue-sync.md`、`layout.json` 版本與備份位置、id 穩定檢查結果、各段重出清單、`verification.json`（含接點 0 px、音訊相關）、關鍵時刻靜格與分鏡、誠實的剩餘限制。這些資料應足以讓另一個對話修改單一頁面，而不用回讀整段製作歷史。

## 多 agent 分工

- 各自擁有一個頁面資料夾與預覽埠；共享的原簡報、素材來源與片頭參考專案維持唯讀。
- 曾有效的分工：便宜模型探索與盤點、中階模型實作、頂級模型只審靜格、分鏡與驗證數字。
- 並行 agent 不得編輯同一檔案：工程（`tools/`、`src/engine/`、驗證與輸出）與視覺（`src/scenes/`）分開，彼此以檔案邊界協調。
- 不終止不是自己啟動的伺服器；啟動伺服器的 shell 設 `PORT`，工具 shell 另設 `MG_URL`。
- 完成後回報實際產物與已驗證的行為。製作細節與陷阱見 [episode-production.md](episode-production.md)。
