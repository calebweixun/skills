# 03 — 派工 Prompt 模板

> 用法：抄整段、填 `【】`、發給 subagent。三件套（目標動機／驗收／回報）已內建，不要刪欄位。
> 每份模板頂部標了建議 model × effort；與 references/dispatch.md 對照表一致，環境不同時以 00 檔實測為準。

---

## E-1 搜尋／探索（model: haiku, effort: low；優先直接用內建 Explore agent）

```
【目標】在 codebase 中找出：【要找什麼，例：所有呼叫 db.write 的位置】
【動機】【為什麼要找，例：準備把同步寫入改為批次，需要完整影響面】
【範圍】搜尋範圍限定：【目錄/檔案類型】；明確排除:【例：tests/、generated/】
【驗收條件】
- 每個結果附 檔案路徑:行號
- 明確回答「是否可能有遺漏」（搜尋方式的盲區，例：動態呼叫、字串拼接）
【回報格式】
- 結果清單（路徑:行號 + 一行說明），按【分類方式，例：模組】分組
- 未解決/不確定清單（可為空，欄位必留）
- 禁止：貼超過 3 行的程式碼片段、貼完整檔案
```

## E-2 實作（model: sonnet, effort: medium；涉及並發/安全/複雜狀態時 high）

```
【目標】實作：【功能一句話】
【動機】【這個功能為誰解決什麼問題——遇到規格沒寫到的歧義時，按這個動機取捨】
【輸入】相關檔案：【路徑清單】；既有慣例參考：【指出一個同類實作當範本】
【邊界】不可修改：【路徑/模組】；不可引入新依賴（如需要，先回報停止）
【驗收條件】
- 【具體行為 1，例：POST /x 回 201 且寫入 DB】
- 新增測試覆蓋上述行為且全綠：跑 【測試指令】
- lint 無新增錯誤；git diff 不含意圖外檔案
【回報格式】
- 改動摘要 ≤10 行 + 涉及檔案:行號
- 測試輸出的最後 5 行（證明綠）
- 遺留 TODO / 未覆蓋 case 清單（可為空，欄位必留）
```

## E-3 重構（model: sonnet, effort: high）

```
【目標】重構：【對象】，從【現狀】改為【目標形態】
【動機】【為什麼值得重構——防止 agent 順手擴大範圍】
【不變式】重構前後以下必須完全不變：【對外行為/API/輸出格式】
【驗收條件】
- 既有測試全綠（重構前先跑一次記錄基準：【測試指令】）
- 無行為變更：【驗證方式，例：對同一輸入 diff 前後輸出】
- 改動限於：【路徑範圍】
【回報格式】
- 重構決策 ≤5 條（動了什麼、為什麼這樣動）
- 前後測試結果對照（各取最後 3 行）
- 「我沒動但建議之後處理」清單
```

## E-4 研究／查網（model: sonnet, effort: medium；純撈資料可 haiku）

```
【目標】回答：【問題】
【動機】【這答案要拿去做什麼決定——決定研究深度與側重】
【來源要求】優先官方文件/一手來源；每個論斷附 URL；【時效要求，例：只要 2025 後的資訊】
【驗收條件】
- 直接回答問題（先結論後論據），不要只丟資料
- 相互矛盾的來源要並列並說明你採信哪個、為什麼
- 查不到的部分明確標「未證實」，不准推測補洞
【回報格式】
- 結論 ≤5 行 → 論據（每條附來源）→ 未證實清單
- 總長 ≤【40】行；更長的細節落檔到【路徑】只回報路徑
```

## E-5 審查／驗收（model: sonnet, effort: high；必須是 fresh context，不能是產出者）

```
【目標】驗收以下產出：【路徑/diff 範圍】
【背景】原始任務：【貼上當初派工的目標與驗收條件——原文照貼，不要轉述】
【你的立場】你是驗收者，不是修理者。找問題、給證據，不要動手改。
預設懷疑：產出者聲稱完成，你的工作是試圖證明它沒完成。
【驗收條件】逐條核銷原始驗收條件，每條標 PASS/FAIL + 證據（檔案:行號 或 指令輸出）
【額外檢查】
- git diff 有無意圖外改動
- 有無隱藏 TODO/hack/被跳過的測試
- 【該任務型態的特定風險，例：並發安全、輸入驗證】
【回報格式】
- 判定：ACCEPT / REJECT（REJECT 必附可執行的修正指示）
- 逐條核銷表
- 風險備註（就算 ACCEPT 也要寫，寫「無」也是一種寫）
```

---

## 使用備註
- **鏈式編排由主對話負責**：subagent 不能開 subagent，所以「E-2 實作 → E-5 驗收」
  是主對話先後發兩個派工，把 E-2 的回報餵進 E-5 的【背景】。
- E-5 的驗收者拿到的是**任務描述原文**而不是產出者的自述，這是刻意的——
  防止驗收者被產出者的框架帶著走。
- 模板可以按環境微調，但三件套欄位（目標動機/驗收/回報）不准刪，刪了就退化成普通指令。
