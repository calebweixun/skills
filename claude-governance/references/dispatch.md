# 01 — 模型調度守則

> 讀者：擔任主對話的任何模型（含 Sonnet、Haiku）。規則寫成可直接執行的判準。
> 模型型號以 `references/diagnostic.md` 的「本環境實測結果」為準；下表的別名（haiku/sonnet/opus）
> 是 Claude Code 的官方別名，若實測選單不同，以實測為準並回寫 00 檔。

## 1. 指揮官不下場（何時必須派 subagent）

主對話**必須**委派、不得親自執行的操作：
| 操作 | 判準（達標就派） | 派給誰 |
|---|---|---|
| 讀檔探索 | 預估要讀 >2 個檔案或 >200 行才能回答 | 內建 `Explore`（Haiku、唯讀）或自訂搜尋 agent |
| 掃 repo / grep | 任何「找出所有…」「X 在哪裡定義」類問題 | 同上 |
| 查網頁 | 需要開 >1 個網頁，或網頁內容只是中間材料 | 研究型 agent（模板 E-4） |
| 批次改檔 | 同一種修改套用到 ≥3 個檔案 | 實作型 agent（模板 E-2），模式解出後可降級批量套用 |
| 跑長輸出指令 | 預期輸出 >100 行（測試全跑、build log） | 派 agent 跑並只回摘要＋失敗行號 |

主對話**可以**親自做的：讀單一小檔確認關鍵事實、改 1–2 個檔案的小修、與使用者對話、做決策。

**例外**：如果整個任務本身很小（預估 5 分鐘內、單檔、無探索需求），開 subagent 的固定成本
（重讀 context）反而更貴——直接做，不要為了守規則而守規則。

## 2. 派工三件套（每個委派 prompt 必含，缺一不發）
1. **目標與動機**：要做什麼＋為什麼（動機讓 agent 遇到歧義時能自行做對的取捨）。
2. **驗收條件**：可機械檢查的完成定義（測試通過、檔案存在且含某段落、回答涵蓋某清單）。
3. **回報格式**：明確規定回什麼、不回什麼（見第 4 節回報合約）。

現成模板在 `references/templates.md`，直接抄，不要即興。

## 3. 模型 × effort 對照表（顯式指定，不用預設）

subagent 的 model 與 effort 寫在 frontmatter（`model:` / `effort:`）或派工時指明。
主對話用 `/model` 與 `/effort` 設定。

| 任務型態 | model | effort | 理由 |
|---|---|---|---|
| 搜尋、grep、讀檔摘要 | haiku | low | 機械性工作，錯了便宜重跑 |
| 模式已知的批次修改 | haiku 或 sonnet | low | 模式由上游解出，這裡只是套用 |
| 一般實作、重構、寫測試 | sonnet | medium–high | 主力工作馬 |
| 複雜除錯、架構決策、需求歧義 | sonnet high 起手；卡關升 opus | high | 先用便宜的高 effort，不夠再升 |
| 審查／驗收 | sonnet | high | 驗收品質不能省；但用 fresh context 而非更貴模型 |
| 高風險判斷（不可逆操作前、安全相關） | opus（或環境內最強可用模型） | high 以上 | 見 references/judgment.md 第 1 節升級判準 |

注意：
- effort 等級各模型不同（low/medium/high 普遍支援；xhigh/max 僅部分模型）。設了不支援的等級，
  Claude Code 會自動降到該模型支援的最高等級，不會報錯——所以寫錯不會炸，但要知道實際跑的是什麼。
- 單回合要更深推理可在 prompt 內加 `ultrathink` 關鍵字，不改 session 設定。
- **禁忌組合**：haiku × max effort（付推理費但模型層級吃不下）；opus × low effort（付旗艦價叫它別想）。

## 4. 回報合約（寫進每個派工 prompt）

Subagent 回報**只准包含**：
- 結論（≤10 行）
- 關鍵證據的 `檔案路徑:行號` 引用
- 長產物：落檔到指定路徑，回報只給路徑
- 明確標註的「未解決／不確定」清單（可為空，但欄位必須在）

**禁止**：貼整段檔案內容、貼完整工具輸出、覆述任務描述。
主對話收到違反合約的回報：取用結論、丟棄大段內容，不要複製進後續 prompt。

## 5. 升降級路徑

**升級**（換更強模型重做）：
- haiku 級 agent 做錯**一次** → 直接升 sonnet 重派，不重試。
- sonnet 級 agent 同一子任務**連錯兩次** → 帶完整失敗軌跡（做了什麼、錯在哪、已排除什麼）升 opus。
  失敗軌跡是升級的必要條件——沒有軌跡的升級等於讓貴模型重新踩一遍坑。
- 任何模型同一件事**最多重試兩輪**。第三輪強制換路：換做法、升級、或停下問使用者
  （怎麼選見 `references/judgment.md` 第 3、4 節）。

**降級**（省錢）：
- 貴模型解出「可複製的模式」（例如：確立了一種修改的正確寫法）→ 把模式寫成明確指令，
  降回 haiku/sonnet 低 effort 批次套用到其餘案例。
- 降級套用的結果仍要抽查驗收（≥3 件或 10%，取大者）。

## 6. 驗證不自驗

- **原則**：產出者與驗收者必須是不同 context。同一個 context 會繼承同樣的盲點。
- **檔案改動** → read-back：派 fresh agent（或最少限度：主對話自己重新 Read 該檔）確認
  寫入內容與意圖一致、沒動到不該動的區塊。
- **程式碼** → 測試或實跑，以退出碼與輸出為準，不以「看起來對」為準。沒有測試就先寫最小煙霧測試。
- **高風險判斷**（架構選型、不可逆操作、對外承諾）→ 二選一：
  (a) 第二意見：派 fresh-context agent 給同樣輸入、不給你的答案，比對結論；
  (b) 多答案評審：產 2–3 個候選，派 fresh agent 按明確 rubric 選優。
- **限制（誠實標註）**：subagent 只有一層深——subagent 不能再開 subagent。
  所以「產出→驗收」的鏈要由主對話編排：先派 A 產出，收到後再派 B 驗收。

## 7. 內建 agent 速查
- `Explore`：唯讀、預設 Haiku，codebase 搜尋首選，零設定成本。
- `Plan`：plan mode 內的研究 agent，唯讀。
- `General-purpose`：能讀能寫能跑，用於「邊查邊改」的一體任務。
- 自訂 agent 放 `.claude/agents/`（專案）或 `~/.claude/agents/`（個人），YAML frontmatter
  必填 `name`、`description`，建議明填 `tools`（最小權限）、`model`、`effort`。
